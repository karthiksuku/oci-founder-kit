# 0.7.0 preview: one workflow from application to operations

The preview connects an explicit-environment `oci-kit` interface, additive
packaging, scoped foundation preparation, private operating observations and a
durable SaaS example. Start with [the workflow](WORKFLOW.md); see the generated
[capability table](CAPABILITIES.md) for prerequisites and limitations.

## Included

- Start, status, next, doctor, package, foundation, release, verify, observe and
  support operations over the existing records and exact-plan approval gates.
- Next.js standalone, FastAPI and existing-Dockerfile packaging with source
  preservation, image inspection, credential checks and isolated health probes.
- Separate compartment, network, private-state and registry preparation, private
  configuration handoff and an administrator packet for missing permissions.
- Bounded read-only observations, optional scoped reported costs, a private
  dashboard, release records and preparation of a new reviewed rollback plan.
- An optional customer-request SaaS example with private attachments, durable
  PostgreSQL inbox/outbox and job ledger, a separately scoped Queue worker,
  signed webhooks and duplicate/crash recovery checks.
- Safe local support exports, exact release-archive SPDX inventory, consumer
  provenance verification and prepared dependency/release workflows.
- Build, Migrate and Continue website journeys with searchable guides and
  explicit local-tested capability labels.

## Verification record

The [published v0.7.0 preview record](https://github.com/karthiksuku/oci-founder-kit/releases/tag/v0.7.0)
contains the exact tested manifest, completed checks, per-attempt agent results,
manual-review findings and artifact identities. Read those results before treating
this preview as accepted for your use case. This source document describes scope;
its feature list is not a passing test record.

Release results are recorded separately so the evaluated source and manifest stay
frozen through artifact creation and publication. Earlier failed, interrupted and
superseded attempts remain part of the record. Automated fixture checks and manual
claim review are reported separately; neither is presented as live OCI acceptance.

The agent trials use actual agent CLIs through a restricted local tool harness.
They independently check application behavior, source preservation, environment
selection and stopping before cloud work. They do not establish ordinary
unrestricted-agent or live OCI acceptance. Requested and observed model identity
are recorded separately; unavailable host model metadata is explicitly unknown.
A trial's successful blocked/resume behavior is not proof of recovering an
actually interrupted cloud operation.

## What remains pending

No OCI write was performed for this preview. Full new-app and hosting-first
acceptance still requires current exact approved plans and resolution of the
sandbox IAM boundary. HTTPS deployment, hosted sign-in, live two-user isolation,
persistence, isolated restore, actual cloud rollback and effective cross-role
IAM denial remain unverified by this preview. Reused foundation outputs are
owner-supplied evidence until checked against the actual approved resources.

GitHub-hosted checks, authenticated attestations and immutable-release acceptance
remain pending because the publication credential lacks workflow permission.
Prepared workflow templates are not successful Actions runs. This manual preview
contains reproducible assets and hashes, but no authenticated build attestation;
the strict consumer provenance verifier will correctly refuse missing provenance.
The stable/latest release pointer is unchanged.

Linux x86_64 is the tested local platform. macOS and WSL2 remain unverified.
Native Resource Scheduler/Functions scheduling remains experimental and blocked
on its separate artifact and invocation acceptance. The default single-instance
topology can interrupt service during updates and rollback.

Hosting-first migration keeps external data, authentication, storage and worker
ownership until separately reviewed transfers. Saved preferences, evidence and
release records never grant approval. No automatic telemetry or support upload
is introduced. Private vulnerability reporting is enabled through the security
reporting route described in [SECURITY.md](../SECURITY.md).
