# Enterprise-buyer readiness pack

Enterprise deals often stall in security and procurement review rather than
on the product. List what buyers will ask for, what exists today and what is
missing. The value is measured in days of review and deals not lost, using
the founder's own deal history.

## What buyers usually ask for

| Area | Evidence buyers look for | Notes |
|---|---|---|
| Data residency | Which region holds their data, backups and logs; where support staff can access it | Check the live OCI region list and that every service used is offered in the required region |
| Security posture | Security policy, access control, encryption at rest and in transit, vulnerability management | Answer from what the founder runs, not from the cloud provider's certifications alone |
| Certifications | Which certifications the founder's company holds | Provider certifications cover the provider's controls; they do not certify the startup |
| Identity | Single sign-on, role-based access, audit logs | Usually a product feature, not an infrastructure one |
| Availability | Uptime target, recovery time and recovery point, tested restores | Promise only what has been tested |
| Data handling | Data processing agreement, subprocessors, retention and deletion | The cloud provider is a subprocessor; list it |
| AI use | Which models process customer data, where, and whether data is used for training | Check the model provider's and Oracle's current AI terms |
| Commercial | Procurement route, private offers where applicable, payment terms | Ask whether the buyer already buys through Oracle |

## Measuring the value

```text
review days before   = median days from first questionnaire to signature (last 5 deals)
review days after    = the same, after the pack exists
deals lost to review = count, from the founder's pipeline notes
```

Report these as the founder's own numbers. Do not estimate an industry
average.

## Rules

- Do not state that the startup is compliant with a standard because it runs
  on a provider that is.
- Do not write security answers the founder cannot evidence.
- Keep questionnaire answers versioned and dated; they become commitments.
